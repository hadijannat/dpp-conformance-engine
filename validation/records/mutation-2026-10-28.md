## Survivors of the baseline

### Method

`uv run mutmut results --all true` listed 1060 survived mutants.
For each of them, `uv run mutmut show` wrote the diff to a file.
A development agent read the diffs of the survivors of the changed modules.
It wrote a test for each group that it judged killable.
It wrote a reason for each mutant that it judged equivalent.
Scratchpad scripts then did four things. They recorded the class of each mutant from rules that name the mutant. They ran each new test alone under each mutant that the test names. They compared the results of mutmut before and after each re-run. They wrote the tables below.
A mutant without a rule is "not classified".

Four aids supported the reading. They are not part of the repository:

- A differential harness set `MUTANT_UNDER_TEST` to one redaction survivor and ran 120015 generated inputs through the functions of `redaction.py`. It printed the first input whose output differed from the original. A mutant that differed gave an input for a test. A mutant that did not differ got the reading of its code that the table gives as its reason.
- A property check of 292620 random tokens compared the forms that `_forms` gives. It found one case: the plain form of a token that starts with "/" is part of its JSON-escaped form.
  No other form is part of another. That fact decides which sort mutants of `_forms` are killable.
- A comparison of `_routable` with its two surviving mutants over 800009 IPv4 and IPv6 addresses found no address with a different result.
- A run of the whole suite inside `mutants/` under one mutant (`SystemResolver.resolve` mutant 3) ended with exit status 0. No test fails under that mutant.

The classes are these:

- Killed by a new test: a survivor that a re-run killed and that a test of this round kills alone. The table calls the class "killable".
- Killed by an existing test: a survivor that a re-run killed and that no test of this round kills alone.
- Equivalent: the mutant cannot change behavior on any input, or no input of the program reaches the difference. The reason is one line. "This host only" and "this Python only" mark a reason that depends on the host or on the Python version.
- Out of scope: the mutant changes only the wording of a detail in the report of the standalone verifier. That report is not part of a decision body, and the codes, the outcomes, and the digests stay the same.
- Not classified: no reader judged the mutant.

Text that enters a canonical body is not out of scope. This holds, as in the earlier record, for `TestResult.message` and for `verdict_reason`.
That group holds the messages of the JOSE profiles, the manual results, the timestamp checks, the disclosure files, and the key reader.
Tests kill them.

### Findings

- No survivor shows a defect. A survivor shows that the tests do not notice a change. It does not show that the code is wrong.
- One group of survivors shows a rule that no test pinned. When a token starts with "/", its plain form is part of its JSON-escaped form. The order of the forms in `_forms` decides whether a scrubbed echo leaves a backslash. Three sort mutants of `_forms` are killable, and two are equivalent.
- No test inside the mutation run passed `--opening` to the standalone verifier. The tests of `tests/test_disclosure.py` that do so carry the marker `qr`, and the configuration excludes that marker. Mutants 56, 59, 112, 113, 114, 148, and 154 of `main` survived the baseline.

## Tests added

All tests are in `tests/test_mutation_gaps_round4.py`. The file holds 80 test functions, which `pytest --collect-only` counts as 171 test cases.
The file changes no file under `src/`.
No test has the marker `validation`, `qr`, or `aas`, so mutmut runs them and the job without the extras runs them.
Every server is a loopback server that the test starts. A name that is not a loopback name resolves through a table.
Every key, token, and secret is a TEST-ONLY value. No test contacts another host.
Each test names the mutants that it kills in its docstring.
The numbers refer to the source at `5824386`. A change of a function can move them.
Two expectations for the Location `mailto:////;` once depended on `urlunparse`. CPython 3.12.3 drops its empty authority, and 3.12.12 keeps it.
Since 2026-10-29, the engine joins URL parts with the rules of CPython 3.12.12 and 3.13 on every Python.
The helpers are `url_unsplit`, `url_unparse`, and `url_join` in `redaction.py`.
The two tests expect the 3.12.12 answer again, on every Python. The mutation runs used 3.12.12.

The tests reuse helpers and tables of other test modules: `tests/test_credential_schemes.py`, `tests/test_manual_results.py`, `tests/test_report_status.py`, `tests/test_timestamps.py`, `tests/test_mutation_gaps_round2.py`, and `tests/tsa_support.py`.
They only import these helpers. No assertion of another module changed.

For each pair of a test and a mutant in the docstrings, a script ran that test alone with `MUTANT_UNDER_TEST` set to the mutant.
A failing run confirms the pair. The table counts the confirmed pairs.
The pair of `test_the_token_request_names_the_engine_and_asks_for_json_without_encoding` and `_request_token` mutant 52 did not run through that script.
On 2026-10-29, two review agents ran that test alone under that mutant, and it failed.

## Open

- The plain command `uv run just mutation` ends with exit status 1 in the collection of statistics. Three tests fail inside the `mutants/` tree, and the baseline deselects a fourth as a precaution. A maintainer decides whether the configuration should deselect them. This record does not change `pyproject.toml`.
- Mutants not classified: 71 in `dppce.evidence.timestamp` and 4 in `transport.py`, as the table above lists. The 71 need crafted DER tokens. Examples are a token that is not CMS SignedData, one without a TSTInfo, one with the version 2, one with trailing data, and one whose genTime has an offset. The 4 in `_send` (mutants 90, 92, 93, and 109) need a TLS server that fails after the handshake while the deadline has passed.
- The 26 timeouts are not classified.
- The 31 mutants that the baseline killed and re-run 1 did not: the cause of the difference is not known.

- Defects: none found. No survivor showed an input for which the code is wrong.

## Limits of this record

- Mutation testing shows that the tests notice a change. It does not show that the code or the tests are right.
- An agent classified the survivors. No person has reviewed this record. A different reader can classify a mutant differently.
- The run used one host. 16 survivors are equivalent on this host only or on this Python only. Their reasons depend on `os`, on the Python version, or on the tables of `ipaddress`.
- mutmut 3.8.0 mutates only the bodies of functions and methods, as the earlier record states. Its limits about module-level constants hold. The new modules add constants that mutmut does not mutate. In `status.py` they are `STATUS_LIST_TYP`, `MIN_BITS`, `MAX_BITSTRING_BYTES`, `MAX_TOKEN_BYTES`, `_ENCODED`, `_STAMP`, and `_FILE_CODES`. In `disclosure.py` they are `MAX_OPENING_BYTES`, `MAX_PROOF_BYTES`, `NOT_CHECKED`, and `NOT_ORDERED`. In `jose_profiles.py` they are `ALGORITHMS`, `VC_TYP`, `REFUSED_ALGORITHMS`, `MAX_BODY_BYTES`, `MAX_SIGNATURES`, `ENGINE_LIMITS`, `_B64URL`, `_COMPACT`, `_DATE_TIME`, `_ECDSA`, and `_CURVES`. The command was `grep -nE '^[A-Za-z_][A-Za-z0-9_]*: Final'` over the three files.
- The new tests import `MAX_PROOF_BYTES`, `MAX_OPENING_BYTES`, `MAX_BITSTRING_BYTES`, `MAX_TOKEN_BYTES`, and `MAX_BODY_BYTES` instead of repeating the numbers. They follow a change of these constants and do not detect it. This run does not show whether any test detects such a change.
- Some tests kill a mutant by an exact comparison of text that HTTP treats as equal. An example is the case of the header names of the token request. Such a kill pins the spelling that the engine writes. It does not show a difference on the wire.
- The four tests that the baseline deselects did not take part in any run. A mutant that only one of them could kill counts as survived.
- The 31 mutants that the baseline killed and re-run 1 did not show that a run can contain kills that a repeat does not reproduce. The counts of killed mutants in this record are the counts of single runs.
