Audience: maintainers and assessors.
Purpose: record what mutation testing showed about the tests of the verdict and evidence code.
Prerequisites: read `docs/readiness.md`, section 2.

"Detected" counts killed and timed-out mutants. Two timeouts are in `merkle.verify_inclusion`
(mutants 31 and 36): the mutant loops without end, and the test run stops it. In run 5 the third
timeout is `recording._descriptor_reader` mutant 21: without the non-blocking flag, a FIFO in place
of a record blocks, and the test run stops it.

Run 5 mutates more code than run 4: the fixes of review round 2 added the descriptor-based purge
and the reader functions of `evidence/recording.py`. Between run 4 and run 5, tests were added for
the gaps that the survivors of the round-2 code showed (`tests/test_review_round2.py`), and the
function `read_verified_index`, which had no caller, was removed.

An earlier attempt did not test any mutant. mutmut copied only the mutated directories, and
the copy could not import `dppce.models`. The configuration now copies `src/` and excludes the
other modules from mutation. That attempt is not in the table.

Between the runs, tests were added for the gaps that the survivors showed. See
`tests/test_mutation_gaps.py`. One gap was a defect: a token with a part that is not
base64url was reported as `BAD_SIGNATURE`. It is now `MALFORMED`.

## Limits of this record

- Mutation testing shows that the tests notice a change. It does not show that the code or
  the tests are right.
- The classification of the survivors was done by a script and checked by reading, by a
  development agent. A different reader can classify a mutant differently.
- The run used one host. The case-insensitive file system hides one mutant.
